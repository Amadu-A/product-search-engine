# Частичная структура из локального JSON

Редакция от 18 ноября 2026. Проверенный исходный `main` совпал с GitHub:
`06498a5ff70130fcf30e1fe575031e00e0710810`. Доработка остаётся незакоммиченной.

**IMPLEMENTED; TESTED LIVE в изолированной PostgreSQL taxonomy_test.**
Файл владельца `data/input.json` загружен через новый CLI в отдельную временную
schema, повторно применён и проверен SQL. Рабочая БД `aistation` не изменялась;
её deploy/import выполняет владелец по [docs/import.md](../import.md).

По текущему решению владельца локальный технический импорт не требует
permission/review и допускает complete=false. Сведения `license=UNKNOWN`,
`usage_status=unverified` и пустое уведомление сохранены без подмены. Никакого
фиктивного разрешения нет: новые audit review/permission имеют SQL NULL.
Повторного парсинга, HTTP-запросов и обхода блокировок в этой доработке не было.
Ограничения HTTP-адаптера сохранены; его доступ отделён от импорта файлов.

SHA-256 исходного input.json:
`0d00832ab127bcfe5a56be8a55a000f05fbc451f976b0acbd9af6f94c8787803`.
Исходные JSON и отчёт сборщика остались побайтно неизменными. Нормализация выполнена
отдельно, преобразований названий в текущем файле — 0, ценовые подписи сохранены.

Группы признаков пересекаются; это эвристические предупреждения, не подтверждение
товарной природы каждой записи. Все 2775 узлов импортированы с исходными названиями;
132 записи доступны для отдельной проверки через quality_flags и отчёт.
Пустые flags также не подтверждают достоверность категории. Полнота внешнего каталога
не доказана; список URL всех 192 страниц в отчёте сборщика отсутствует.

Машинные результаты и эксплуатационный SQL-отчёт находятся только в `.tmp/`:
`.tmp/reports/real-input-validation.json`, `.tmp/reports/real-input-import.md`,
`.tmp/reports/pytest-real-input.xml`. Тестовая schema удалена штатной фикстурой после
проверки. Это доказательства тестового запуска, не отчёт о production aistation.

Регулярный набор проверок: 79 тестов с реальной PostgreSQL; отдельно — один тест
исходных 2775 узлов. Покрыты миграции, дополнение детьми, update источника, custom,
ручной конфликт, rollback категорий/снимка/аудита и отчёт о полноте/качестве.
Windows quality gate проходит; результаты прогонов и coverage находятся в `.tmp/`.

После серверного импорта команда `report` создаст фактический отчёт по aistation
в `.tmp/reports/petrovich_taxonomy_import.md`, со своими counts, SHA и audit runs.
Товары, цены, Excel и frontend в эту доработку не входят.
