# Исправления после ревью 75e1198

База — `main` `75e11984824ae83211514f5c29753016c961acf6`.
Локальный HEAD, GitHub и сервер сверены. На aistation подтверждены рабочий HTTP
по `192.168.55.3:8092`, Alembic 0003, 2540 категорий и прежняя контрольная
сумма UUID. На момент проверки `ingest_jobs` в рабочей БД был пуст.

Выбор через видимую кнопку и drop теперь обновляют один список файлов.
Оператор видит размер, готовность и ошибки каждого файла. Файлы можно удалять
до отправки. Список, счётчик кнопки и multipart используют один набор данных.
Во время отправки виден прогресс. Backend остаётся источником истины для
проверки формата и размера. Playwright проверяет фактический POST с границей
multipart, ошибку разбора JSON и успешное создание preview.

При назначении конкретной позиции создаётся или переиспользуется Product.
Распознавание из исходного имени, ручное назначение и восстановление
старых строк используют уже существующие связи записи. Если связи нет,
создаётся самостоятельный provisional Product. Миграция не требуется.
Устаревший `assigned` без Product помечается замечанием. Его можно
восстановить командой `reclassify`, сохранив утверждённый UUID категории
и автора решения, без исходного файла. При повторном вызове восстановленные
строки исключаются из отбора.

Отчёт и UI показывают `assigned_count` для исходных строк,
`products_created_count` для Product с записанным заданием создания,
`categorized_products_count` для уникальных связанных Product с категорией
и `assigned_without_product_count` для старых незавершённых назначений.
Атрибуция создания для уже существующих Product старого выпуска отсутствует.

## Выбор категории

Из 51 назначения C в «Кабель, провод» в сохранённом AITIM-прогоне 50 получили
`broader` непосредственно из `answer_2`. Один результат пришёл из обхода.
Теперь допустимый широкий результат с детьми запускает уточнение от выбранного
узла. Если более узкая категория не подтверждается, сохраняется подходящий
широкий результат. При отклонении гибридного результата по исключению обход
начинается от корней. Все вызовы входят в прежний бюджет позиции.

Вместо списка товарных условий в Python проверяются утверждённые семантические
исключения категории и её предков. Для буквального исключения фраза вводится
отдельной строкой. Существующие шаблоны `answer_1`, `answer_2` и `answer_3`
сохранены. Иерархический результат дополнительно проходит `answer_2`.
Если у изделия неизвестно назначение, а ветка не имеет утверждённого описания
назначения, неподтверждённый выбор остаётся на проверке. Связь с исходным
наименованием проверяется по пути и утверждённым алиасам. Такая проверка может
оставить на проверке синоним без алиаса. Совпадение слов само по себе категорию
не утверждает.

На изолированном стенде использованы сохранённые `answer_1` и настоящее shared
VLM. Для «Лоток почкообразный» проверены выбор обхода и конкретный прежний
кандидат «Сантехника → Аксессуары для ванной комнаты». Подходящей категории они
не подтвердили. Для «Кабель ВВГнг силовой 3×2,5» уточнён путь
«Электрика → Кабель, провод → Силовой кабель». Полный эксперимент A/B/C
остаётся историческим, заново он не запускался.
