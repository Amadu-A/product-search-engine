# Каталог товаров

Главная страница `/` читает существующий каталог PostgreSQL. У категории
показано количество доступных товаров во всей ветке. Ветка в фильтре включает
сам узел и активных потомков. «Без категории» показывает товары с пустым
`category_id`. Товары в архиве скрыты.

Таблица поддерживает поиск по названию и артикулу, фильтр производителя,
сортировку и серверную пагинацию. При поиске артикула пробелы, дефисы и регистр
можно опустить. Карточка показывает характеристики, полный путь категории,
производителя, бренд, артикул, продавцов и исходные ссылки. Отсутствующие
данные показаны явно. Из карточки можно перейти по сохранённой HTTP(S)-ссылке.

## API

| Запрос | Данные и параметры |
| --- | --- |
| `GET /api/v1/categories/tree` | Узлы с UUID и путями. `product_count` — прямые назначения, `subtree_product_count` — вся доступная ветка |
| `GET /api/v1/products` | `q`, `category_id` или `uncategorized=true`, `manufacturer_id`, `sort`, `offset`, `limit` |
| `GET /api/v1/products/{id}` | Карточка с `category_path`, `features` и `source_links`. Архивный или отсутствующий товар возвращает HTTP 404 |
| `GET /api/v1/products/{id}/offers` | Предложения и продавцы, `offset` и `limit` по предложениям, `history_offset` и `history_limit` по наблюдениям каждого предложения |
| `GET /api/v1/manufacturers` | Имена производителей, привязанных к доступным товарам, и статус сведений |

Сортировка принимает `created_asc`, `created_desc`, `name_asc`, `name_desc`
и `mpn_asc`. По умолчанию API сохраняет `created_asc`. При одинаковом значении
основного поля порядок определяется UUID.

Цены выдаются как исторические наблюдения с исходной датой, временем сохранения
и доступными сведениями о верификации. Если дата источника отсутствует,
интерфейс показывает дату сохранения отдельно. Неизвестные валюта и единица
остаются пустыми. API не формирует текущую цену или наличие товара.

## Справочники

Явно заполненные поля `manufacturer` и `brand` при создании Product пополняют
отдельные справочники и связываются с товаром. Повторы одинакового имени с
разным регистром переиспользуют запись-кандидат. Продавец хранится отдельно
в предложении. Статус кандидата не подтверждает юридическое лицо или
идентичность изделия. Правила сопоставления Product сохраняют приоритет
подтверждённых идентификаторов и проверку вариантов.

## Подготовка массового импорта

Ревизия `0004_catalog_read_model` пересчитывает счётчики существующих заданий
один раз и применяет дельту при каждой транзакции с изменением строк задания.
Индексы ограничивают стоимость привязки предложений, поиска исходных строк
карточки и сортировки. `bash scripts/up.sh` делает резервную копию собственной
PostgreSQL перед обновлением с `0003_catalog_pipeline`.

Команда `bash scripts/test.sh --catalog-load` создаёт 25 000 синтетических строк
в изолированной PostgreSQL с утверждённым соответствием категории. Прогон
меряет подготовку, обработку, отчёт, поиск и пагинацию. Его результат сохраняется
в `.tmp/reports/stage04-catalog-load.json`. Время вызовов shared VLM в этот
замер не входит.

Отдельный `tests/test_rabbitmq_live.py` проверяет real AMQP с изолированной
тестовой очередью, действующими правами проекта и mock-инференсом. Он держит
задание дольше интервала heartbeat, проверяет SQL lease, повторную доставку и
восстановление просроченного задания.

### Замер на aistation

В изолированной PostgreSQL распределены все 25 000 синтетических строк.
Preview занял 2,29 с, транзакционная подготовка 72,08 с, обработка 327,11 с,
отчёт 3,15 с. Подготовка выполняется синхронно, поэтому ответ на запуск
крупного задания приходит после фиксации исходных строк.

| Запрос каталога | Медиана из 7 запросов |
| --- | ---: |
| Первая страница | 7,15 мс |
| Последняя страница | 52,14 мс |
| Поиск по наименованию | 79,45 мс |
| Поиск по артикулу | 45,75 мс |
| Фильтр производителя | 24,84 мс |
| Выбор ветки | 58,50 мс |

AMQP-прогон с паузой 62,01 с подтвердил доставку, продление lease,
игнорирование повторного уведомления и восстановление после истечения lease.
Большой тест использовал утверждённое соответствие категории и SQL-транспорт,
а AMQP-тест использовал собственную временную очередь в существующем vhost.
Скорость большого импорта с классификацией C и shared VLM этими замерами
не определяется.
