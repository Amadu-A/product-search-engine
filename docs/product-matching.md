# Идентичность изделий и объединение каталога

Импорт сначала сохраняет исходник, предложение и наблюдение цены. Ручное
решение и связь с уже обработанной исходной записью имеют приоритет. Для
новой позиции проверяются исходные структурированные реквизиты. Если их
недостаточно, используется сохранённый или новый `answer_1`. Профиль версии 2
сохраняет происхождение артикула, марки, модели и технических характеристик.

Поиск по `product_identity_keys` проверяет до 32 активных кандидатов. Полный
артикул, модель, марка, серия и сохранённый URL используются для поиска.
Автоматическая связь требует совместимых подтверждённых фактов. Код продавца,
гипотеза модели, похожее написание или один кандидат с неполным профилем
оставляют запись на отдельной карточке. Для кабеля без MPN сверяются полная
марка, число жил, сечение, напряжение и бренд либо изготовитель. Отличия IP,
цвета, крепления, суффиксов, размеров по осям и других известных параметров
блокируют связь. Единица и фасовка предложения сохраняются на Offer.

После решения `same` предложение получает действующую категорию Product.
Классификатор C работает для нового или впервые классифицируемого Product.
Решение `uncertain` и UUID кандидатов видны в `import-report` по заданию.
Если найдено несколько доказанных карточек, запись остаётся на проверке до
объединения. Первый корректный заголовок остаётся основным. Цена в каталоге
сопровождается датой исторического наблюдения.

## Предварительный план

`merge-products` читает PostgreSQL в транзакции `READ ONLY`. План содержит
связи, причины отказов, исходники, продавцов, исторические редиректы, отдельные
присоединения исходников без Product и ожидаемое уменьшение числа карточек.
Обычное продолжение импорта применяет новый поиск к оставшимся позициям.

По умолчанию план использует накопленные сведения. `--verified-facts` принимает
отдельный список проверенных оператором документов. Один документ содержит
`document` с URL, `claims` с `brand` и `mpn` и при необходимости `model`,
`mark`, `series`, `manufacturer`, список `type_terms` и словарь `features`.
Например, `"features": {"voltage": ["220"], "power": ["5"]}`. Указывайте
документ, где подтверждены код и исполнение изделия. Сначала проверяется
применимость документа к исходной записи. Файл входит в хеш плана. Во время
импорта, preview и apply сетевые запросы к таким страницам отсутствуют.

```bash
docker compose --env-file .env.example --env-file .env run --rm -T --no-deps app \
  merge-products --verified-facts .tmp/reports/identity-verified-facts.json \
  | tee .tmp/reports/identity-production-preview.json
```

## Применение утверждённого плана

После выкладки `main` и миграции `0006_identity_physical_merge` сформируйте
свежий preview. Передайте владельцу SHA-256 плана. После подтверждения SHA
запустите `merge-products --apply --expected-sha256 "$SHA" --idempotency-key "$KEY"`
с теми же `--verified-facts`. Активные задания блокируют применение. При
изменении снимка потребуется новый SHA. Повтор с тем же ключом возвращает
прежний результат.

Одна транзакция переносит ссылки, сохраняет старейший UUID и имя, ручную
категорию, полный набор предложений, исходники и цены. Поглощённые карточки,
включая подтверждённые старые алиасы, физически удаляются. Старые UUID ведут
на действующую карточку, даже при последовательных объединениях. Обычные
карточки `retired` исключены из плана. При расхождении счётчиков, хешей или
связей транзакция откатывается. После commit без резервной копии полное
восстановление удалённых карточек не гарантируется.

## Проверки

`bash scripts/test.sh --identity-load` запускает 25 000 синтетических строк
на временных PostgreSQL и Qdrant, через отдельную очередь project RabbitMQ.
Проверка использует mock inference. Снимок каталога для benchmark берётся
локально из `examples/identity_benchmark`, стандартный тестовый набор от него
не зависит. На Windows выполните `./ops/check-quality.ps1`, затем запустите
replay из PowerShell.

```powershell
$env:PYTHONPATH = '.'
& .tmp/venv/Scripts/python.exe tests/identity_benchmark.py --output .tmp/reports/identity-benchmark-after.json
& .tmp/venv/Scripts/python.exe tests/identity_benchmark.py --facts .tmp/reports/identity-verified-facts.json --output .tmp/reports/identity-benchmark-with-facts.json
```
